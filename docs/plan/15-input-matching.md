# 15 · 输入匹配：砍尾巴最长匹配机制（设计文档）

> 本文是**纯逻辑设计**，不写代码。术语不懂看 `docs/glossary.md`（说人话版）。
> 状态：**设计中**。逻辑全部说通 → 模拟验证 → 才落代码。

## 1. 要解决的问题（一段话）

用户打了一串码（全拼/简拼/混合都行），引擎要回答一个问题：
**这串码里，最长能匹配到词库里的哪个词？**

- 打 `nihao` → 整串命中"你好" → 匹配长度 2（2 个音节）
- 打 `bsyzsgcy`（背水一战是个成语 的简拼）→ 整串没有 → 从尾巴一节节砍：
  `bsyzsgcy`(8) → `bsyzsgc`(7) → `bsyzsg`(6) → `bsyzs`(5) → `bsyz`(4) ✅ 命中"背水一战" → 匹配长度 4
- 选中"背水一战"上屏后，剩 `sgcy` **继续走同一流程**（续接）

## 2. 核心规则（三条）

### 规则 1：输入先切分成"段"

字母串按音节切分成段（`'` 强制分隔，其余贪心最长合法音节）：

| 输入 | 切分结果 | 段类型 |
|---|---|---|
| `nihao` | `[ni, hao]` | 全拼段 ×2 |
| `bsyzsgcy` | `[b,s,y,z,s,g,c,y]` | 简拼段 ×8（单字母） |
| `h'a` | `[h, a]` | 简拼段 + 全拼段 |
| `xi'an` | `[xi, an]` | 全拼段 ×2（`'` 强制切） |

**段类型**：
- **全拼段**：一个完整合法音节（`ni`、`hao`），匹配"码里对应位置是一个该音节的词"
- **简拼段**：单字母（`b`），匹配"码里对应位置是一个以 b 开头的音节的词"
- **非法段**：不是合法音节也不是单字母前缀（理论不发生，兜底保留）

约定：**一段 = 一个音节位**。全拼段锁死具体音节，简拼段是"以该字母开头"的通配。

### 规则 2：砍尾巴 = 从最长段前缀开始，**逐级全部输出**（M1 已落地）

对段序列 `[d1, d2, ..., dn]`：

```
for k = n, n-1, ..., 1:            # 从最长前缀开始，逐段砍尾巴
    取前缀 [d1..dk]
    每级：viterbi 组句（0 或 1 条）+ 词库 exact（词/单字，按权重）
全部候选按 k 从长到短排列
```

**要点**：
- **逐级全出**：不是"第一个命中即停"（旧理解，M1 已改为逐级输出）——
  整句 → 次长句 → … → 词 → 单字都进候选列表，用户翻页总能到达所需层级；
  输入过长歧义大时用户自然退格缩小范围（有选择，而非没得选）。
- **匹配 = 前缀**：命中的是"前 k 段"，尾巴（第 k+1 段往后）留给续接（M3）。
- **砍的是段，不是字符**：简拼时一段=1 字母（所以看起来像逐字母砍）；全拼时一段=1 音节。
- 每级词候选上限 20；同 k 内 Sentence 在前、词按权重降序。

### 规则 3：选词后，尾巴续接（**M1 已落地**：picked 栈 + 悬空续接）

- 用户选中匹配的词 → 该词**悬空入栈**（不上屏、无 commit 信号）→ **尾巴（第 k+1 段之后）留在会话里，重新走规则 1+2**；已选词通过预编辑混合显示反馈（`床前ming'yue'guang`），候选窗只列尾巴候选
- 例：`chuangqianmingyueguang` 选"床前"（消费 2 段）→ 悬空入栈、预编辑 `床前ming'yue'guang` → 候选"明月光/明月/明…" → 空格上屏"明月光"（全消费 → `Commit(床前明月光)` 全量上屏）
- 例：`nihao` 选"你"（消费 1 段）→ 剩 `hao` 续接出 hao 的词
- Esc：有已选词 → 已选词上屏（`Commit(picked.join(""))`，尾巴取消）；无 → 整句取消
- 退格：有已选词（picked 栈）时**取消一次栈顶**（code 拼回 raw 头部，混合显示自动还原为全拼音）；无已选词时删尾巴字符（真退格）
- **M3 剩余**：picked 的逐词光标编辑（§4 编辑段：已消费段一路退回）、cursor 概念的显式建模（当前以 seg 截断等价实现）

## 3. 匹配的具体语义（段模式 → 词条）

词库给每条词按音节切好（编译期完成），存两张表：

| 表 | 键 | 值 |
|---|---|---|
| 全拼表 | 全拼码（`beishuiyizhan`） | 词条列表（按权重降序） |
| 简拼表 | 简拼码（`bsyz`） | 词条列表（按权重降序） |

**段序列 → 查询**：

| 段序列 | 查什么 |
|---|---|
| 全是全拼段 | 全拼表 exact（`[ni,hao]` → `nihao`） |
| 全是简拼段 | 简拼表 exact（`[b,s,y,z]` → `bsyz`） |
| 混合段 | 展开成"全拼码模式"查全拼表：简拼段用**以该字母开头的任意音节**匹配。实现：把简拼段替换为 `[a-z]*?` 通配，词库侧逐条匹配；命中 = 该词条全拼码能被这组段模式完整消费 |

**混合段的匹配方式（细化）**：对词库中每个候选词条（或经简拼表粗筛的集合），
把它的全拼码按音节切分后与段序列**逐位对齐**：

```
段序列   h        '        a
         简拼段           全拼段
词条     hao      +       a        → 好啊 ✅（h=好 的首字母，a=啊）
词条     ha       +       a        → 哈啊 ✅（h=哈 的首字母）
```

对齐规则：全拼段 = 音节必须完全相等；简拼段 = 音节必须以该字母开头。

**性能**：混合段场景（有简拼段）先用简拼表粗筛（`h` 开头的音节 → 词条子集），
再在该子集内做段对齐。全拼/全简拼场景走 exact，O(1)。

## 4. 编辑（预编辑可修改）

会话中（含选词后剩尾巴时）预编辑随时可改：

- **退格**：删最后一个字符 → 重新切分 → 重新砍尾巴。已上屏的词不受影响；已消费的段可一路退回（退到空）。
- **`'`**：强制分音节 → 改变段边界 → 重新砍尾巴。
  - 例：`niha` 选"你"后剩 `ha` → 退格删 `a` 剩 `h` → 打 `'` → 打 `a` → 预编辑 `h'a` → `h`(简拼)+`a`(全拼) → "好啊"出在候选 1。
- **字符**：直接追加 → 重新砍尾巴。

**编辑只影响会话内的段序列，不回溯已上屏文本。**

## 5. 会话状态（引擎内部）

会话维护：
```
raw（原始输入串，可编辑）
seg（当前切分段序列）
picked（已消费并确认的词，如 "背水一战"）——上屏由 TSF 层决定时机
cursor（段位置，默认 0）
```

- 候选 = 对 `seg[cursor..]` 执行砍尾巴的匹配结果
- 选词：`picked += 词`；若消费段数 = 剩余段数 → 会话结束（上屏 picked）
  若消费段数 < 剩余段数 → `cursor += 消费段数`，尾巴继续匹配
- 退格：优先缩尾巴（删末尾字符/段），cursor 相对回退；`picked` 可清空重选

## 6. 边界与降级

| 情况 | 行为 |
|---|---|
| 整串砍到 1 段仍无匹配 | 无候选，只显示切分预览（如 `s'g'c'y`），用户可退格/补全拼 |
| 词库缺失（透明模式） | 全部按键放行，不匹配 |
| 词条权重相同 | 按词条文本排序（确定性） |
| 混合段匹配过多 | 简拼表粗筛 + 权重降序截断（上限可配置，默认不设限跟随微软） |

## 7. 验收例子（模拟脚本必须全过）

1. `bsyzsgcy` → 砍 8→4 → 候选首条"背水一战"；选 1 上屏，剩 `sgcy` 续接
2. `bs` → 2 段命中，所有 b+s 首字母词按权重降序，翻页可达（不设限）
3. `nihao` → 整串命中"你好"（现有 exact 路径不变）
4. `nih` → `[ni, h]` 无整词 → 砍到 `[ni]` → "你/泥/妮…"；选"你"后 `h` 续接
5. `niha` 选"你" → 剩 `ha` 单字候选（少，可能不满一页，照常显示）
6. `h'a`（强制分隔）→ "好啊"候选 1（简拼+全拼混合段）
7. `xi'an` → 西安；`xian` → 先（强制分音节经典场景，**M1 已实现**：词库键空格→`'` 分隔化 + 无撇号枚举切分合并；`xian` 混排含"西安"按权重排序）
8. 编辑：`niha` 选"你" → 退格删 `a` → 打 `'` → 打 `a` → `h'a` → "好啊"候选 1
