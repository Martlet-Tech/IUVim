# 55 · 设置页用户库词条操作

状态：**开工**（2026-10-15）。前置（词库页 Grid 化显示）已落地，见 settings.rs `dict_tab`。

## 1. 需求

词库页目前只能看（155 条覆盖/自造 + 屏蔽列表），无任何单条操作。自造词打错无法除名、异常权重（一排 8000）无法修正。本任务给词条行提供操作能力。

## 1.5 已定决策（2026-10-15 评审，防反复横杠）

- **A 生效语义**：单条操作（删除/改权重/屏蔽互转/新增）**立即生效**（mutation 即执行即写盘，与输入法内 Shift+←/→ 一致）；仅「清除全部/导入」维持两段确认。可逆性靠绝对值语义天然保证（再 Set 回来即可）。
- **B 调权配对**：一次 Swap 写两条独立覆盖记录，文件格式无血缘字段，**不做配对删除**。行级删除语义诚实（删该词覆盖=恢复静态权重，另一条自洽保留）；同 code 的行按 BTreeMap 序相邻显示；**同 code 表头组级操作「清除此拼音全部调权」**（循环 Remove）作粗调兜底。
- **C 导出格式**：与主词库源格式（`compile.rs` 词条行）完全一致——空格分隔音节，导出文件可直接喂回 dictc；导入时撇号/空格都吃（归一化）。
- **D 导入冲突**：同 (code, word) 按导入值覆盖，不做逐条选择交互。
- **E 新增校验**：**纯格式校验**（2026-10-15 真机反馈放宽）——非空、仅小写字母/撇号、无空段；**不查音节表**，用户可自定义缩略语（如 cj）。原「每段须在音节表内」方案挡掉了缩略语这一合法需求，废弃。

## 2. 现有可复用设施（全部现成，零协议改动）

- 变更枚举 `UserMutation::{Swap, Set, Remove, Block, Unblock}`（`iuv-data/src/userdict.rs`，proto 为 re-export）与 `UserDict::apply_mutation` 一一对应：
  - 删除/恢复默认 = `Remove`（只清覆盖表，TSF Shift+Delete 既有语义不动）；改权重/新增自造词 = `Set`；屏蔽 = `Block`；取消屏蔽 = `Unblock`（55 开工新增变体，只清屏蔽表）
- 传输：`C2S::UserMutation`（iuv-proto，postcard serde），TSF 客户端已在用；设置页在 server 进程内，直接调引擎 `apply_user_mutation` + `UserDict::save` 写盘，与「清除全部」同路径。
- 列表 UI：`egui_extras::Table`（55 开工引入，主智能体批准 2026-10-15，见 01-contract §2.2）——粘性表头 + 斑马纹，替代早期 Grid 方案（Grid 表头随滚动丢失、无行分隔，2026-10-15 真机反馈）。

## 3. 任务分解（三梯队，按序做）

### 第一梯队（代码已落地，待真机回归）

- [x] **单条删除**：行尾按钮，按 B 决策区分——覆盖词「↺ 恢复默认」、自造词「× 删除」，均对应 `Remove`（`Engine::has_base_entry` 新增查询区分显示）。
- [x] **组级清除**：拼音分组表头行「清除调权」（循环 `Remove` 该 code 下所有覆盖，不碰屏蔽表）。
- [x] **搜索过滤**：卡片顶部 `TextEdit`，按拼音子串或词条子串实时过滤（大小写不敏感）。
- [x] **点表头排序**：拼音（默认，分组渲染）/ 权重 升降切换，表头按钮 + 方向标记。

### 第二梯队（代码已落地，待真机回归）

- [x] **改权重**：权重单元格点击进入行内编辑，回车提交（`Set`）/ Esc 取消；非法数值红字提示保持编辑态。「恢复默认」= 第一梯队的 ↺（同为 `Remove`）。
- [x] **屏蔽/取消屏蔽互转**：覆盖词行「屏蔽」按钮 = `Remove` + `Block` 单次落盘（`dict_block_from_cover`）；自造词不显示（Remove 即消失，屏蔽无意义）。取消屏蔽 = 第一梯队屏蔽行 ×。
- [x] **新增词条**：表格上方三输入框（拼音/词条/权重，权重缺省 8000 = 引擎 `PHRASE_DEFAULT_WEIGHT`）。`Set` upsert 语义：基础库没有 = 自造词，有 = 覆盖权重。校验（决策 E 放宽版）= `Engine::valid_code` 纯格式校验，自定义缩略语（cj 等）放行。**位置偏差**：计划写「列表底部」，实际放表格上方——Table 占满剩余高度会挤出下方内容（同「清除全部」问题），待第三梯队工具行重排归位。

### 第三梯队

- [ ] **列表工具行重排（2026-10-15 评审定稿）**：表格上方一条工具行——搜索框居左，「清除全部 / 导入 / 导出」居右；表格吃掉剩余全部高度（Table 默认占满可用高度的脾气转为优点，顺带根治「清除全部被挤出 640×480 可视区」问题）。清除全部的两段式确认原地渲染在工具行位置（`pending_clear/confirm_clear` 状态机不动）。
- [ ] **导出**：用户库导出为文本文件。用户库本体是二进制（`IUVUSR02`，`%LOCALAPPDATA%\iuv\`），用户无法直接带走 → 换机同步/备份是正当需求。格式复用主词库源格式 `词<TAB>拼音<TAB>权重`；屏蔽条目以 `#屏蔽` 前缀行表达（人类可读、可 diff、可手动增删）。
- [ ] **导入**：解析导出格式，逐条走 `Set`/`Block` 合并进现有库（非整库替换——两机各自积累的调权可并存；同 (code, word) 冲突按导入值覆盖）。导入即走既有「确定/应用」落盘路径。
- [ ] **文件选择对话框（决策点）**：`rfd` crate（egui 生态标准，需白名单审批）vs 用已有 `windows` crate 调 `IFileOpenDialog`（COM，零新依赖，约 50 行）。届时定夺。

### 不做

- 云同步/自动同步：M10 架构下 server 是唯一服务进程，未来可评估，当前明确不做。
- 行内改拼音/词条：等价「删 + 增」，拆开走删除/新增更干净（避免脏数据）。
- 以二进制文件直拷为同步手段：全量覆盖会砸掉目标机已有调权，与合并语义冲突（导出文本方案天然解决）。

## 4. 实现要点

- 决策 A：单条操作立即 `apply_user_mutation`（引擎内存态）→ `UserDict::save` 写盘 → 更新面板快照，三处一致；落盘时机与「清除全部」同路径（防 2026-08-18 复活 bug 同型回归）。仅「清除全部/导入」走两段确认。
- 搜索框/排序状态存 `SettingsApp` 字段，`user_dict_snapshot` 返回的 rows 在渲染前过滤/排序。
- 屏蔽表展示：屏蔽行同样行尾「×」（删屏蔽=取消屏蔽）。
