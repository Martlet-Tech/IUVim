# 键盘处理流程（按键路由与会话语义）

> 定位：iuv 按键处理的**权威行为规格**——从原始按键到候选栏/上屏的完整链路。
> 机制层（这些行为在 TSF 层如何发生：EditSession/Range/Composition/光标等）见
> [`../knowledge/tsf-interaction.md`](../knowledge/tsf-interaction.md)。
> 源起 issue「d冒号表现不一致」（`docs/issue/d冒号表现不一致.txt`）：会话内符号键曾被
> 放行给应用，各程序插入位置各异（`:d` / `d:` / 的:）。本文件同时标注与【新增】，
> 【新增】两条即该 issue 的修复内容（符号进序列、越界数字字面化）。
>
> 设计原则（2026-08-22 用户定稿）：**切分器不认识的字符（标点/大写）自动成为单字符段，
> 含此类段的输入只产「原文兜底候选」**（无序号、Space/Enter 上屏、随输入实时刷新）——
> 不引入"字面模式"之类的显式状态，一切由既有 原文兜底 管线自然实现。


对用户输入的按键 有两个存储字段  
1个是原始用户输入 （以下叫 原始缓存）  
数据单向从捕捉到的用户输入->到原始缓存

另一个是音节切分器处理结果显示 （以下叫 分节缓存）  
数据单向从音节分割器->分节缓存->显示到预编译

## 一、路由层（每个按键的第一站）

1. **不可见字符**（F1/Home/PgUp/方向键/Ctrl 组合等）→ **放行**给应用
   - 会话内例外：Shift+←/→ = 调权、Shift+Del = 隐藏候选
2. **可见字符**分派：
   - **标点**（中文模式、会话外）：命中中文标点表 → 直接上屏全角形（`,`→`，`、`;`→`；`、
     Shift+`;`→`：`…引号按开/闭配对翻转）；表外符号（`/` `_`）→ 放行
   - **数字/空格**（会话外）：半角模式放行；全角模式直接上屏全角形（`２` `Ａ` 全角空格）
   - 英文模式：全部放行（全角模式例外，见上）
3. **a-z / A-Z** → 进入原始缓存

## \# 原始缓存非空->启动会话

## 二、会话内（候选栏已启动）

| 按键 | 行为 |
|---|---|
| **Esc** | 取消整个会话, 结束会话, 啥也不上屏 |
| **翻页/移动高亮**（keymap 自定义；默认 `,` `.` ↑↓ PgUp PgDn）| 保持会话, 执行用户快捷键定义的操作 |
| **数字 1-9** | 有对应位候选 → 选词（消费完全部段 → 提交结束；部分消费 → 已选词悬空续接）；**越界/无可选 → 数字字面进序列**（原文候选刷新）【新增；替换旧的静默吞键】 |
| **a-z** | 进原始缓存 |
| **A-Z（大写）** | 进原始缓存 |
| **CapsLock**| 正常生效， 之后收到的大写字母进原始缓存 |
| **Backspace** | **删到了原始缓存变空, 啥也不上屏**。 有已选词 → 删原始缓存末尾的字母/符号； |
| **Enter** | 原始缓存上屏，会话结束 |
| **Space** | 消费候选, 最后一个候选被消费的时候, 预编译上屏, 结束会话 |
| **符号**（`': ; [ \ - = /` 等 OEM 键，±Shift 经 US 布局推导）| 追加进原始缓存, '号也不例外进入原始缓存, 只不过音节分割器的输出在输入的'号位置保留原始的'号|

## 三、贯穿规则（机制层）

1. **切分器容错**：对一切无法组成音节的字符（标点、大写等），切分器产生**单字符段**
   （`segment("d:")` → `["d", ":"]`），保证有解永不失败【现状，Quanpin::backtrack 兜底分支】。
2. **原文兜底候选**：含非音节段的路由判定为 Mixed 且展开不出音节配对 → 候选为空 →
   自动补一条**原文候选**（text = 输入去撇号，kind = Word/Char，seg_len = 段数全消费）
   ——候选窗内容恒非空【现状，engine generate_candidates 末尾】。
3. **原文候选无序号**：UI 层按 `候选文本 == reading 去撇号` 判定，命中则不加 `N.` 前缀
   （layout/render 共用 candidate_label 规则）——字面尾巴天然满足【现状，零 UI 改动】。
4. **锁定是免费的**：`: ` 之后无论追加什么字符，所有切分方案都被该字符毒化 → 永远
   只剩原文兜底 → 自然形成"字面输出意图"；Backspace 删掉毒化字符后拼音候选自动恢复
   【新增行为的机制来源，无需显式状态】。
5. **输出边界统一**：提交文本统一过 宽度转换（全角模式 `nihao`→`ｎｉｈａｏ`、`: `→`： `）
   与 简→繁转换（繁体模式）。字面尾巴跟随全局宽度设置（全角模式下 `:` 出 `：`）。

## 四、实现映射（关键点位）

| 流程节点 | 实现位置 |
|---|---|
| 路由层判定（Test/KeyDown 共用） | iuv-tsf `com/key_routing.rs::route_key` |
| 符号键 → Key::Char 映射（OEM ±Shift） | iuv-tsf `session_bridge.rs::map_key`（TODO：自定义按键映射落地时收编集 = 可打印符号 − 用户已定义功能键） |
| 会话推进（字母/符号进序列、数字选词或字面、编辑键） | iuv-core `session.rs::on_key` |
| 音节切分（含单字符段兜底） | iuv-core `schema.rs::Quanpin::backtrack` |
| 候选路由 + 原文兜底 | iuv-core `engine.rs::classify/generate_candidates` |
| 无序号呈现 | iuv-ui `layout.rs::candidate_label` |
