# 44 号 · AI 输入条（头脑风暴，未立项）

> 状态：点子探索——工具栏与桌宠之间加 AI 输入条（四角星 ✦ logo，默认细条，点击展开 3 行×32 字输入框，
> 输入提示词让 AI 完成任务）。能力接口未定，本文整理输入法的独特权限与建议边界。

## 1. 输入法相比桌面智能体的真实特权

1. **文本注入是系统钦定的**：普通智能体模拟键盘（SendInput）会被反作弊拦、被安全软件盯；
   TSF 输入法本来就是系统认证的文本提供者——**AI 生成文字以"输入"身份合法落入任何文本框**。光标在哪，AI 输出到哪。
2. **原位替换选区**：TSF range 直接替换选中文本——选中→润色/翻译/改写→原位替换，无剪贴板杂技。
3. **输入流内嵌视角**：能感知预编辑与选词（仅限启用 iuv 的应用），做边打边补全/实时纠错的地基，且无键盘 hook 的隐私污名。
4. **跨应用常驻** + 低打扰系统级浮窗：AI 入口搭在工具栏上零教育成本。
5. **反向信任责任**：输入法看得到用户打的一切 →"不记录输入内容"必须是铁律（差异化承诺，见 PRD 对标 Bongo Cat 隐私争议）。

## 2. 能力接口分级（建议边界）

**第一梯队（开放——全是文本进出）**
- 选中改写：润色/翻译/扩写/缩写，原位替换
- 光标续写：Copilot 式补全，但系统级
- 提示词 → 生成 → 进光标（聊天回复/邮件/周报）
- 按前台应用定制模板（前台进程名现有代码就在拿）

**第二梯队（AI 操作输入法自己）**
- "切英文/隐藏工具栏/简转繁"——AI 作为输入法操作员，接口 = 现有 CtlCmd/SetState 体系，零新增权限面

**不开放（守住边界）**
- 文件系统/截屏/浏览器控制——开放即从"文本进出口"变"全权桌面智能体"，权限模型崩坏。

## 3. 架构落点

- AI 后端放 **daemon**（常驻、不碰打字热路径）；HTTP 客户端建议 `ureq`（同步、极小、无 tokio），
  **新依赖走白名单审批**；用户自带 API key（BYOK：DeepSeek/混元/OpenAI 任填）——不垫成本，Steam 免费模式不被污染。
- 稳定性隔离：独立线程 + 超时即败，打字链路对网络零感知——AI 崩了输入法还是好输入法。
- 全屏抑制直接复用（42 号前的全屏隐藏已覆盖工具栏复合窗，AI 条同窗则天然被盖）。
- API key 存 config 的明文风险需在设置页明示。

## 4. 大坑与妙解

**坑**：工具栏是 `WS_EX_NOACTIVATE`——设计上绝不抢焦点（点击不打断打字）；但文本输入框必须收键盘焦点，直接冲突。
展开输入条→临时激活→打断当前 composition，体验就破了。

**妙解**：输入条**不自己收键盘**，复用输入法打字链路——`16-command-mode.md`（命令模式）正是现成的路：
点输入条 → 光标处开 composition 预填 `/` → 用户用输入法打命令与提示词 → 回车 AI 处理 → 结果直接替换。
输入条只是命令模式的可视化触发器；键盘、焦点、候选窗全部白嫖现有链路，NOACTIVATE 一字节不改。

## 5. 排期建议

排在 **M2b（Lua mod）之后**——mod 化是 Steam 大方针的轨道，AI 条是增值功能。
其中「选中改写 + 提示词进光标」性价比极高，可作为独立小步先试水（一个 ureq + 一个 TSF range 替换即可跑通 Demo）。
