# 16 · 设计构想：iuv 命令体系（代号 iuvim 的命名由来）

> 状态：构想记录，未实现。命名动机：汉字无 i/u/v 开头音节 → `i`/`u`/`v`/`iuv` 前缀
> 与拼音零冲突，天然可作命令前缀。

## 命名由来

- 汉字拼音没有以 `i`/`u`/`v` 开头的音节（i 系写作 yi、u 系写作 wu、v 只作 ü 替身）
- 因此 `iuv` 位于输入序列首位时，**永远不可能命中任何词**，可无歧义触发特殊功能/界面

## 命令体系

| 前缀 | 模式 | 功能 |
|---|---|---|
| `i` | 表情 | 单键出表情候选；`i`+拼音过滤（如 `ihaha`） |
| `u` | 快捷模板 | 常用语模板（改吧/提交/推送…）；`u`+关键词过滤；用户可扩展 |
| `v` | 工具 | 搜狗/微软 U/V 模式合并：数字转换（中文/大写金额/罗马/日期，候选多格式）、算式计算、M3+ 拆字/笔画 |
| `iuv` | 系统总控 | 设置/皮肤/词库管理/帮助/关于（界面类动作 → M4 Tauri helper） |

## 可行性（已核实）

- `i`/`u`/`v` 单段 → `Route::Empty`；`iuv` 多段 → Abbrev 档 exact 恒空：**四前缀现状全部无候选**，接入命令模式零冲突
- M1 闭环：表情/模板/数字转换 = 选中即上屏文本，走现有 `SessionEnd::Commit` 通道，TSF 无需改动

## 架构方向

- `classify` 加四档（Route::Emoji / Template / VMode / SystemCmd），判定顺序：`iuv` 最先（否则被 `i` 表情吃掉）
- 新 `command.rs` 模块：表情表/模板表/数字转换/表达式求值（纯 Rust 零依赖，求值器自研 ~200 行）
- `CandidateKind` 扩展：Emoji / Template / Command（candidate.rs 注释已预留槽位）
- 用户模板：`%LOCALAPPDATA%\iuv\templates.json`（复用 Config 缺省回退模式）
- iuv 系统命令动作：Effect 加动作字段 → TSF 重载引擎（M1 可做）；设置/皮肤界面 → M4

## 里程碑切分

- **M1.5**（可选）：四档路由 + i 表情（内置表）+ u 模板（内置+JSON）+ v 数字/计算 + iuv 帮助/关于
- **M3+**：v 拆字/笔画（借鉴 Rime 社区数据，GPL-3.0 同白霜词库处理：gitignore 单独存放、不编进二进制）
- **M4**：iuv 设置/皮肤/词库管理 → Tauri helper 面板
