## 2. 点子 A：整句翻译（在线 API）

### 2.1 用户描述（原始）

> 中文模式下用户正常打字操作，键盘停止 0.5 秒，就触发翻译，显示在候选 N+1 号位；
> 用户可以 Tab 过去高亮翻译项，空格上屏翻译结果。

### 2.2 拆解（触发 → 呈现 → 上屏）

| 环节 | 设计要点 |
|---|---|
| 触发 | 中文模式、会话进行中，**键盘空闲 0.5s** → 触发整句翻译。空闲判定在 TSF 层（按键时间戳 + 定时器） |
| 翻译对象 | 当前整句 = 预编辑输入的最佳中文解读（候选首项/整句候选/已选词+尾巴）——需明确取什么文本送 API |
| 在线 API | 未定：Google 非官方 gtx 端点（免费无 key）/ MyMemory / 可配置端点 / 官方商业（需 key） |
| 网络归属 | 输入法进程直连 or 走 daemon（M6 已有管道 + 唯一长驻进程，网络放 daemon 更合架构） |
| 呈现 | 候选窗 **N+1 号位**（所有候选之后）显示翻译项——需扩展 `UiSnapshot`/layout/render 渲染特殊槽 |
| 高亮 | Tab 把高亮移到翻译项（`Key::Tab` + 会话内翻译槽选中态） |
| 上屏 | 翻译项高亮时按 **Space** 上屏翻译结果（替代原文/整句） |

### 2.3 待定决策（未答，用户已搁置）

- **翻译服务选型**：Google 非官方 gtx / MyMemory / 可配置端点 / 官方商业 API。
- **默认开关**：输入内容会发第三方（隐私）——默认开 or 默认关可配。
- **Tab 语义**：Tab = 翻译槽专用，与点子 B（自动补全）**互斥或共存**，需先定分配。
- 目标语言对（中→英？可配？）、翻译延迟/失败降级（超时不显示？）、空闲触发节流。

## 3. 点子 B：自动补全（选词续打）

### 3.1 用户描述（原始）

> 比如打字到 `ces` 预编辑显示 `ce's`，候选已经是「测试」了，用户可以 Tab 一下补全，
> 预编辑变成 `测试|`（光标），然后继续输入。这个手感跟空格上屏其实都是用了一次点击操作，
> 并没省操作，但是总觉得有值得深挖的地方呢。

### 3.2 拆解

| 环节 | 设计要点 |
|---|---|
| 触发 | 会话内按 Tab（`Key::Tab`），作用对象 = 当前高亮候选 |
| 行为 | 把高亮候选**以「已选词」形态钉进预编辑**（类似现有「选中间级词」悬空续接，见 §4），
  但**不结束会话**——`测试` + 光标，之后可继续输入下一段拼音 |
| 与空格区别 | 空格 = 上屏并**结束**会话；Tab = 钉入选词栈**继续**会话——多词连续输入不打断 composition |
| 用户直觉 | 用户自评「跟空格上屏都是单击操作，没省操作，但觉得有深挖空间」——深挖点 =
  把「选词 → 悬空续接」从仅限中间级词推广到**任意候选**（含整词），形成「逐词确认续打」节奏 |

### 3.3 与现有机制的衔接

- 现状已支持「选中间级词悬空续接」：`commit_index` 部分消费（`seg_len < n`）→ 已选词入栈、
  尾巴续接（`床前ming'yue'guang`），**不产生 commit 信号**（2026-08-11 悬空状态修复）。
- 点子 B = 把 Tab 设计为「对**当前高亮候选**强制走悬空路径（即使整词消费也入栈续打）」的快捷键。
- 差异：现在整词消费（`seg_len >= n`）会结束会话；Tab 语义若为「钉入选词栈 + 不结束」，
  则整词也能续打——需扩展 `commit_index`/新增会话分支。

## 4. 两点的关系与共性

- **共用手势**：都要加 `Key::Tab` + `map_key` VK_TAB + `on_key` 分支 + 契约 §4.1。
- **语义冲突**：A 的 Tab = 「移动高亮到翻译槽」，B 的 Tab = 「钉选当前候选续打」——两种不同手势，
  需用户拍板（A 专用 / B 专用 / 共存 / Tab 与 Shift+Tab 分工）。
- **通用底盘**：若 A 要做「N+1 特殊槽渲染 + 槽位高亮 + 槽位上屏」，这套「特殊候选槽」机制
  未来也可承载 B（或反之）。建议：无论做哪个，先把「特殊候选槽」抽象（Effect 扩展）想清楚。
- **会话生命周期**：A 的翻译项上屏 = 会话结束（替换上屏）；B 的钉选续打 = 会话继续。

## 5. 建议实现顺序（若后续推进）

1. 拍板 Tab 语义分配（A/B/共存）。
2. 定翻译服务与开关（若做 A）、定空闲触发与网络归属（daemon or 直连）。
3. 通用改动先行：`Key::Tab` + `map_key` + 契约 §4.1 + 特殊候选槽渲染（`UiSnapshot`/layout/render/candwin）。
4. 按 A/B 各加会话分支 + TSF 接线 + 单测（iuv-core 会话 5+、map_key、layout）。
5. 手测验收（空闲触发、N+1 槽高亮/上屏、续打不回滚、Esc/Backspace 交互）。
