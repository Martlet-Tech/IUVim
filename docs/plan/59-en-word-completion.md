# 59 · 英文单词补全（中英混输不切模式）

> 状态：**待立项（当前优先级最高的新功能）**（2026-10-18）。
> 动机：中文模式下打英文，现状是"原文兜底"——`hel` 直接上屏 `hel`，没有补全。
> 用户要么切英文模式，要么硬打。这是每天撞几十次的摩擦，且 TSF/协议零改动。
> 前置阅读：`01-contract.md`（§4 候选契约）、`02-conventions.md`。

## 1. 目标（验收一句话）

中文模式下输入无法构成任何中文候选的拉丁串（如 `hel`），候选栏给出按词频排序的英文补全
（`hello` / `help` / `held`…），空格或数字上屏；有中文候选时**绝不**出现英文候选。

## 2. 现状（已核实）

- 兜底插入点：`crates/iuv-core/src/rime/mod.rs:114` —— 候选为空时补一条
  `api::raw_fallback_candidate(&plain, n_seg)`（"不认识"语义，候选不编号）。
- 触发条件天然可用：**兜底分支 = 中文完全打不到**，正是英文补全该出现的时机。
- `Config`（`crates/iuv-core/src/config/mod.rs:26`）已是 serde 结构，加开关零成本。
- 词库层 `Dict`（`crates/iuv-data`）是**音节模型**（按拼音切分 + 简拼键），**不适合**英文前缀匹配
  ——故新做一个轻量 `EnDict`，不硬塞进 `Dict`。

## 3. 设计

### 3.1 门控（最保守，误伤最小）

英文候选只在**同时满足**以下条件时追加：

| 条件 | 理由 |
|---|---|
| 走的是原文兜底分支（中文候选为空） | `nihao`/`he`/`xian` 有中文候选 → 天然不出英文 |
| `plain` 全为 ASCII 字母 | 排除 `'`、数字、符号串 |
| `plain.len() >= 3` | 避免 `a`/`i`/`to` 级别噪声 |
| `config.en_completion == true`（默认 true） | 用户可关 |
| 首字符不是已绑定的 i/u/v 功能键 | 与 23 号功能键插件共存（见 §5） |

### 3.2 数据层：`EnDict`（新，~150 行）

```
crates/iuv-data/src/en.rs
  格式 IUVEN01: magic(8) + count(u32) + 索引表[N × (word_off u32, freq u32)] + 词串区
  加载: mmap + 边界校验（同 IMEDIC02 套路，零分配）
  查询: prefix(p: &str, limit) -> Vec<(&str, u32)>
        索引表按 word 字典序 → 二分定位下界 → 顺序扫 starts_with → 按 freq 降序取 top-N
```

- **为什么不用 `Dict`**：`Dict` 的键是音节序列，`hel` 会被当"一个非法音节"而查不到；
  前缀匹配也不在其 API 内。英文只需要"有序词表 + 前缀二分"，比音节模型简单一个量级。
- 编译：`dictc` 增加 `en` 子模式，输入 `word<TAB>freq` 文本，输出 `iuv.en.imedic`。
- 落点：`data/`（gitignore，同白霜词库处理）→ 产物部署到 `%LOCALAPPDATA%\iuv\iuv.en.imedic`。

### 3.3 排序与呈现

- 排序：**纯词频降序**（同频按字母序），不参与中文的 λ 打分管线。
- 位置：追加在原文兜底候选**之后**（原文兜底保持第 1，保证"不认识就原样上屏"语义不变）。
- 数量：最多 20 条（与 `candidate_prefix` 一致），翻页复用现有机制。
- 大小写：输入首字母大写（Shift/CapsLock 保形）→ 候选首字母大写化（`Hel` → `Hello`）。

### 3.4 不改的东西

`iuv-proto` / `iuv-tsf` / 会话状态机 / 候选窗渲染 **零改动**——候选结构与翻页全部复用。

## 4. 数据源与 license（开工前必须闭环）

| 候选源 | 内容 | 状态 |
|---|---|---|
| ECDICT（skywind3000） | 中英词典，含词频/词形/音标 | **license 需核查**（README 标注与实际分发条款要确认），走白名单流程 |
| dwyl/english-words | 纯词表，无词频 | Unlicense（宽松），但缺词频需另配 |
| SCOWL | 分级词表 | 条款较宽松，需核对 |
| google-10000-english | 1 万高频词 + 排名 | 派生数据，来源条款不清 |

**决策**：优先 ECDICT（唯一同时有词频与词形）；license 不过则退回 dwyl 词表 + 自建词频。
无论哪个，**都不入库**（`data/` gitignore），与白霜拼音同规矩，发布时在 NOTICE 声明。

## 5. 与 i/u/v 功能键的冲突（23 号）

23 号计划把 `i`/`u`/`v` 作为功能键前缀（`vip`/`iPod` 这类英文词会被劫持）。共存规则：

- `config.function_keys` 中**该键已绑定插件** → 首字符为该键时不查英文（功能键优先）
- 未绑定（默认状态）→ 正常查英文（`vip` 出 VIP）
- 23 号实现后此判定点已预留，无需返工

## 8. 风险

- **词表质量**：无词频词表会导致 `hel` 首候选是生僻词 → 必须有词频，否则不做。
- **短前缀噪声**：靠 `len>=3` + top-20 截断控制。
- **中英歧义**：靠"有中文候选就不出英文"这条硬门控，宁可少出不可误伤。
- **体积**：10 万词 + 词频约 1~2 MB，mmap 后无感。
