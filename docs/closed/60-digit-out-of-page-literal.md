## 1. 目标（验收一句话）

**候选窗显示出来的每一个序号都能选词；没显示的数字（含 `0`）一律按字面字符进预编辑。**
不再存在"选中看不见的词"，也不再存在"按了没反应"的死键。

## 2. 现状（已核实）

| 位置 | 现状 |
|---|---|
| `session.rs:152-158` | `Digit(n)` 只判 `1..=9`，索引用 **全表** `page*page_size+n-1`，边界判 `idx < all.len()` → 第 1 页按 6 命中第 2 页第 1 个候选并上屏 |
| `session.rs:236` | `Digit(0)` 落防御臂，消费后**无任何动作**（死键） |
| `layout.rs:48-53` | 序号是**页内下标 +1**，所以窗口上最多出现 `1..=page_size`（默认 5）——与按键语义不一致 |
| `session.rs:73-87` | 字面尾巴机制**已存在**：tail 非空时数字/字符追加进 tail，空格/回车上屏整串，退格逐字删 |
| `session.rs:458-484` | 字面态 effect：候选窗呈现一条**不编号**的原文条目（text == reading），会话可见 |
| `key_routing.rs:104-120` | 判定次序已正确：会话内**先查 keymap 组合键表**，未命中才 `map_key` → `Digit(n)` |
| `session_bridge.rs:84` | `VK_0..=VK_9` 全段 → `Digit(n)`（含 0，含小键盘 NumLock 开归一主行） |

结论：缺的只有一件事——**数字臂的越界分支**。其余机制（尾巴、原文候选、按键次序）都已就位。

## 3. 设计

### 3.1 一条规则

```
n ∈ 1..=本页候选数  → 选词（提交）
其余（越界 + 0）     → 字面尾巴追加该数字字符
```

"本页候选数" = `page_candidates().len()`，与窗口上看得见的序号**逐一对齐**。

### 3.2 判定次序（自上而下，前一层命中则后层不参与）

| 层 | 判定 | 结果 | 现状 |
|---|---|---|---|
| 1 | keymap 组合键命中（翻页/候选移动/调权/隐藏） | 消费，走会话动作 | 已有（`key_routing.rs:104-117`） |
| 2 | 数字在本页范围内 | 选词 | 本任务 |
| 3 | 数字越界或为 `0` | 进字面尾巴 | 本任务 |
| 4 | 已在字面态内 | 所有数字（含 1-5）按字面追加 | 已有（`session.rs:76`） |

**`9`/`0` 被绑成翻页时**：第 1 层先命中，`Digit` 根本到不了会话层，无需任何"冲突检测"。
代价只有一个，且是绑定的固有代价：**绑定后该数字无法再作为字面字符输入**（字面态内翻页键被
`_ => {}` 忽略）。文档写明即可，不做特判。

### 3.3 为什么落 `tail` 而不是 `raw`

| | 进 `raw`（拼音序列） | 进 `tail`（字面尾巴，本方案） |
|---|---|---|
| 拼音序列 | 被污染成不可切分词条 `ce'shi6` | **不污染**，`raw` 仍是 `ceshi` |
| 候选 | 需引擎走"单字符段 + 原文兜底"容错路径 | 候选列表原样保留在 `all` 里 |
| 退格恢复 | 触发 `recompute`，候选重置到第 1 页、高亮归零 | `tail.pop()` 后直接 `effect()`，**页码/高亮/候选逐项原样**，零重算 |
| 与既有行为 | 新增一条语义 | 与符号（`:` `/` 等）**同一套机制**，无新状态 |

即：用户"主动退格删掉结尾数字，候选重新有意义"这个体验，走 tail 比搜狗更顺（搜狗要重新切分
并回第 1 页）。

### 3.4 不做例外（a1/a2/a3 落定）

- **a1**：`0` 与 6-9 同等字面化，无例外。前提是 `0` 未被 keymap 绑成翻页（次序见 §3.2）。
- **a2**：`ceshi6` 字面态下空格照常上屏整串（含数字），不特判——**所见即所得**：预编辑显示
  `ceshi6`，空格就上屏 `ceshi6`。
- **a3**：不做任何例外处理——不加"无效序号"闪烁/提示/提示音，不做绑定冲突检测，不做全角特判。

代码形态（示意，非最终）：

```rust
Key::Digit(n) => {
    let n = n as usize;
    if n >= 1 && n <= self.page_candidates().len() {
        self.commit_index(self.page * self.page_size() + (n - 1));
    } else {
        self.tail.push((b'0' + n as u8) as char); // 越界/0 → 字面
    }
}
```

`iuv-tsf` / `iuv-win` / keymap **零改动**（路由与绑定层不动）。

### 4.1 边界与既有行为交互

- **末页不足一页**：超出实际候选数的序号按越界字面化（与窗口显示一致）。
- **无候选**（`all` 空）：任何数字都字面化（兑现 38 号"无可选 → 字面"）。
- **悬空 picked**（已选词未上屏）：越界数字进 tail，预编辑 = `picked + raw + 数字`，空格整串
  上屏——与符号在悬空态的现状一致，不新增规则。
- **小键盘**：NumLock 开 → 归一主行，行为同上；NumLock 关 → 放行（导航语义不变）。
- **Shift+数字**（`!@#$%^&*()`）：仍走 `ShiftChar` → tail，不变。
- **全角模式**：字面态数字保持半角（与 tail 内符号同口径），本任务不处理。

### 5.1 计划外追加：无编号候选日志维度

**动机**：本任务首轮真机验收时，`update()` 完全静默，日志只有按键——"候选窗到底画了什么"
无从核实，只能靠"窗没 hide + 整串上屏"间接推断编号缺失。这是**可观测性缺口**，不是本任务
的功能缺陷，但正好被本任务撞出来。

**实现**（`platforms/windows/iuv-server/src/candwin.rs`）：

| 函数 | 职责 |
|---|---|
| `unnumbered_candidate(snap)` | 复用 **`iuv_ui::candidate_label`** 判定：标签 == 候选文本本身 ⇒ 没加 `N.` ⇒ 无编号 |
| `unnumbered_suffix(snap)` | `show` 日志追加段，免得「候选 N 项」被读成 N 个可选词 |

- `show` 日志末尾追加 `，无编号候选="..."`
- `update` **仅在无编号态出现/消失时**记一条（不逐键记，避免热路径刷日志）
- 判定**必须复用** `candidate_label`（布局/渲染共用的唯一规则）。首版曾自行实现近似规则
  （`候选 == reading 去撇号`），被单测 `d:'t2` 用例当场打回——近似实现与真实规则有偏差，
  这正是"不得写第二份规则"的实例。

4 个单测：字面尾巴态、常规编号态、原文兜底与真词共存、空 `reading` 不误报。

## 6. 风险与取舍

| 风险 | 判定 |
|---|---|
| 误按 6 + 习惯性空格 → 上屏 `ceshi6` | **接受**。所见即所得；搜狗同款。对比"无操作"方案则需额外 UI 反馈才能避免死键感 |
| 字面态一旦进入，1-5 也变字面（tail 锁定） | **接受**。与符号现状一致（`d:` 后按 1 也是字面） |
| 契约表语义变更影响其他实现方 | 已核对：服务端点击选词走 `Digit(row+1)`（`status.md:968`），`row` 恒在页内，不受影响 |

## 7. 不做

- 不做无效序号的 UI 反馈（闪烁/提示/声音）——字面化本身就是反馈。
- 不做 `9`/`0` 绑定冲突检测或自动让位。
- 不改 `page_size` 默认值（5），不动全角数字，不动候选窗编号规则。

## 8. 未覆盖（诚实标注）

- **末页不足一页**的末尾序号字面化：规则上成立（判据是 `page_candidates().len()`），

- **`9`/`0` 被 keymap 绑成翻页**：代码路径上由路由层先命中组合表保证（§3.2 第 1 层），
  未真改 keymap 实测。
- **悬空 picked 态**下越界数字（§4.1）：未单独真机验证，机制与符号进 tail 同源。
