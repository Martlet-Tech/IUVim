# 47 号 · 候选窗定位语义反转：锚定会话起点（不再跟随尾端光标）

> 状态：**已结案**（2026-09-10），分支 `feat/candwin-anchor-start` 两次提交：
> `ea94381`（锚定语义，修"出现/消失闪烁"）+ `4de4b66`（治本，修"出现瞬间下沉"）。
> **真机手测通过**：打字期候选窗恒定不动、只换内容；折行不跳位；拖拽/滚动/缩放仍随文档平移。
> 范围：`platforms/windows/iuv-tsf`（`composition.rs` / `com/text_service.rs` / `session_bridge.rs` 注释）；
> `iuv-core` / `iuv-data` / `iuv-ui` **零改动**（已合并的 46 号成果与 B0 对拍不受影响）。

## 1. 背景与用户裁决

**现象**：打字时候选栏**每键都随预编辑尾端右移**，内容与位置同时变化——眼睛要确认"最新（末尾）候选"时不好读。

**用户裁决（逐字）**：

> 「跟随光标的感觉其实不好, 预编译在打字时候不断延长, 候选内容也在不断延长, 就导致眼睛想确认最新(末尾)候选内容时候不那么容易, 每敲一个键, 内容和位置都在抖动.
> 反而固定在会话开始位置更舒服. 那样就是预编译和候选在同一个起点一起延展.」

即：**定位语义由「跟随尾端光标」反转为「锚定会话起点」**——候选窗与预编辑同原点一起向右/向下延展，打字期窗口不动。

## 2. 归因：为什么此前"有时跟随、有时固定在会话起点"（真机日志实证）

四次 notepad 会话（`%TEMP%\iuv-tsf.log`，按 pid 拆分统计）：

| 会话 | pid | 会话内焦点事件 | `[follow]` 条数 | 表现 |
|---|---|---|---|---|
| 11:07 | 29008 | 有 `OnSetThreadFocus`（会话开始前） | 大量（x 1737→2143…） | 跟随 |
| 11:22 | 28856 | **无** | **0** | 固定 |
| 11:37 | 1644 | **无**（首个 focus 行是 11:38:15 切出时的 `OnKillThreadFocus`） | **0** | 固定 |
| 11:39 | 29036 | 有（`Activate` 之后 114ms） | 20（x 1737→1881） | 跟随 |

**因果链**：

1. 窗口位置只有两个更新点——首键 `ui.show(&snap, caret)`（定位）与布局跟随 `follow_layout → move_to`；
   窗口已可见时按键走 `ui.update(&snap)`，而 `CandidateUi::update` **不带 caret** → **不重定位**。
   所以"没有 sink"⇒ 位置从首键 `show` 起被冻结整场。
2. 布局 sink 的唯一挂载点是 `ITfThreadMgrEventSink::OnSetFocus`，而 TSF 的焦点通知**只在焦点变化时发一次、绝不重放**：
   若本输入法是在"焦点早已落在该窗口"之后才被激活（先点进窗口、再 Ctrl+Space / 语言栏切过来），
   该事件已发给上一个 TIP；我们的 sink 挂上时事件早过去了，此后焦点未再变化 → **sink 整场缺席**。
3. **决定性证据**：会话 A 的线程焦点 sink（`Activate` 时挂载）整场**只收到 `OnKillThreadFocus`、
   从未收到 `OnSetThreadFocus`**——一个已挂好的"获得焦点"监听器整场不响，唯一解释是它挂上时该线程
   已持有焦点；同一时刻文档层的 `OnSetFocus` 自然也已发生过。会话 B 反之：`Activate` 之后 114ms 才来
   `OnSetThreadFocus`（焦点在激活**之后**获得）→ 事件送达 → sink 挂上 → 20 条跟随。

**用户侧可操作判别**：新开窗口 / 先激活输入法再让窗口获得焦点 → 跟随；窗口先有焦点、再切到本输入法
（或 Ctrl+Space 换档）→ 固定。本方案修掉该缺口后**不再随机**；且按新语义，sink 只负责
"拖拽/滚动/缩放的锚点平移"，打字期一律不动。

## 3. 方案（三处，均在 iuv-tsf）

**P1 锚点量取（抖动根因）**
- `SetTextSession`：选区收尾**仍折叠到末尾**（光标必须落在预编辑之后，输入法正常行为），
  但其后对同一 range 再 `Collapse(ec, TF_ANCHOR_START)` 再 `GetTextExt` → 量到 **composition 起点**。
- `RepositionSession`：`TF_ANCHOR_END` → `TF_ANCHOR_START`（布局跟随路径同口径）。
- 收益：共享 `caret` 槽语义整体变为"锚点"，`show` 定位 / `move_to` 目标 / 跳变检测基线
  三处**自动统一**，无需新增状态字段（起点在打字期恒定，故窗口稳定）。

**P2 补齐 sink 挂载（锚定的前提）**
- `activate()`：`GetFocus() → GetTop() → advise_layout(来源=Activate)`（覆盖"激活时焦点早已就位"）。
- `OnKeyDown`：首键懒挂（`layout_sink.is_none()` → `advise_layout(来源=首键)`）兜底无焦点文档的窗口期。
- `advise_layout` 增加来源参数，并在**挂载成功**时记一行日志（此前只有失败日志，
  "没挂上"只能靠"整场无 follow 行"反推——正是第 2 节归因时被迫采用的手段）。

**P3 锚点去重**
- `follow_layout`：新量取矩形与共享 `caret` 相同 → 只更新槽、跳过 `move_to`。
  锚定后打字期坐标恒定而宿主仍每键发 layout 事件（实测 20 条/9 秒）；
  2026-08-29 曾在"跟随尾端"语义下以"收益测不出来"撤销该去重，**锚定后它才真正生效**。

## 4. 预期效果与连带改善

- 打字期窗口**恒定**在会话起点，只有候选内容变化 → 消除"内容与位置同时抖动"。
- **折行不再隐藏/跳位**：跳变判定基准变为锚点位移；正常打字与折行都不触发；
  点击远处/拖拽窗口仍按既有语义（大位移 → 隐藏 → 下一键在新锚点重现）。
- 拖拽窗口 / 滚轮 / 缩放：锚点随文档平移 → 窗口随之平移（sink 缺口修复后不再随机失效）。

## 6. 边界

- Electron/Chromium 宿主 `GetTextExt` 恒失败（既有边界，`caret_probe_fails` 达上限后早退）→
  无锚点坐标可量，窗口保持原位不动；不在本任务范围。
- 预编辑折行时候选窗留在**第一行**（锚点未移动），这是"与预编辑同原点"的直接推论，属**预期行为**。
- 依赖白名单不变（零新增 crate）；TSF 红线：绝不 panic 到宿主进程、绝不在 `OnLayoutChange` 回调内 advise/unadvise。

## 7. 实施修订（真机日志驱动的两次纠偏，终版以本节为准）

第 3 节 P1 记的是「对同一 range 再 `Collapse(TF_ANCHOR_START)` 后 `GetTextExt`」——**该写法已被真机
日志证伪并在 `4de4b66` 取代**，两轮现象与根因如下（均以 `%TEMP%\iuv-tsf.log` 逐条对拍得出）：

**修订 1：候选栏"一会出现、一会消失"**（`ea94381` 已修，此处记录证伪过程）
- 症状：打字期候选窗出现/消失交替（日志里 `[perf] render … show` 反复出现、`update` 极少）。
- 根因：写会话里那个 range 已被 `Collapse(TF_ANCHOR_END)` **退化成尾端一个点**，退化区间没有跨度，
  对它再 `Collapse(START)` 是原地不动 → 打字路径量得的仍是**尾端**（x 逐键右移 1868→1959），
  而布局跟随路径用新 range 折叠起点、恒定读到**起点** 1643：两路差 316px > `JUMP_THRESHOLD`(150px)
  → 跳变检测每隔一键误判"输入点远跳"→ 藏窗 → 下一键又 show。
- 排查提示：本机 `config.json` 的 `disabled_log_modules` **含 `candwin`**，跳变藏窗那条日志被静音，
  只能靠 `render show/update` 的比例反推；排查该类问题时应临时移除该项。

**修订 2：候选栏"出现瞬间往下沉一下"**（`4de4b66` 修复，终版形态）
- 症状：候选栏出现后约 32ms 向下挪 2px。
- 数据：同一锚点测到的盒尺寸随**时机**变——会话首键（刚 `SetText` 完）是**字形盒** `w/h=23/21`，
  布局稳定后是**行盒** `0/23`，而 `x/y` 完全相同（真机 34 次量取：15 次字形盒、19 次行盒，
  20 次 `锚点平移` 全是行盒）。
- 终版两处改动：
  1. **锚点量取收敛为唯一只读路径**：`set_text` 不再在写会话内 `GetTextExt`，改为写会话结束后调
     `query_caret`（只读会话，与布局跟随**同一份代码**）；`SetTextSession` 随之删掉量取分支与
     `caret` / `caret_probe_fails` 两个字段（净减 60 行）——写会话内量取正是"两路各量一个盒"的根源。
  2. **去重只认锚点位置**：`follow_layout` 的判据由"整矩形相等"改为只比 `(x, y)`。`position_in_area`
     的下方偏移含 `caret.h`，比全字段会让首键 `show` 之后必然多一次 `move_to`（21→23 即 2px 下沉）；
     锚点位移才是"需要跟文档平移"的事件（拖拽/滚动/缩放时 `(x,y)` 真变，仍照旧移动）。
- 验收：`cargo check -p iuv-tsf --all-targets` 零告警、`cargo test -p iuv-tsf` 38 通过 + 真机手测。
